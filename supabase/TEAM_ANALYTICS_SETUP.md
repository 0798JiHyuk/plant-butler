# 팀 통계 / 가구 방향 적용

현재 DB 적용·백업·복구 절차는 [MIGRATIONS.md](MIGRATIONS.md)를 우선한다.
아래 SQL 실행 안내는 해당 기능 최초 도입 기준이며, 적용한 과거 파일을 재실행하지 않는다.

## SQL과 팀 권한

기존 4개 마이그레이션 뒤에 아래를 순서대로 SQL Editor에서 실행한다. 적용한 과거 마이그레이션은 수정/재실행하지 않는다.

1. `migrations/20261118010000_team_analytics.sql`
2. `migrations/20261118020000_share_furniture_direction.sql`

기존 PRD 모양의 `events`가 있으면 재사용한다. `events`에 일반 클라이언트의 직접 접근 권한은 주지 않고 검증된 RPC로만 기록한다. 다른 프로젝트에서 서로 다른 `events` 구조를 이미 쓰고 있다면 적용 전에 충돌 여부를 확인한다. 새로 만든 모든 테이블은 같은 마이그레이션에서 RLS를 활성화한다.

팀원이 게임에 Google 로그인한 뒤 Dashboard → Authentication → Users에서 해당 계정 UUID를 확인한다. 아래는 관리자만 SQL Editor에서 실행한다. 사용자 metadata나 브라우저 플래그로 팀 권한을 부여하지 않는다.

```sql
insert into public.analytics_team(user_id)
values ('팀원_GOOGLE_UID'::uuid)
on conflict do nothing;
```

여러 팀원은 행을 추가한다. 권한 취소:

```sql
delete from public.analytics_team
where user_id = '팀원_GOOGLE_UID'::uuid;
```

등록 후 게임의 설정을 다시 열면 **팀 통계** 버튼이 보인다. 목록을 읽는 것은 본인 행만 가능하다. 집계 RPC는 매번 Google 인증과 팀 테이블을 다시 검사한다. 팀원은 원본 이벤트·회고·계획·이메일·정원 저장 JSON을 조회하지 못하고 집계값만 받는다. 지정된 팀 계정은 집계에서 제외된다.

별도 서버, 외부 분석 서비스, 새 API 키는 필요 없다. SQL 적용 후 최신 프런트엔드를 반영해야 한다. 운영 DB에는 이번 작업에서 직접 적용하지 않았다.

## 지표 정의

- 로그인과 저장 복원이 끝나 게임을 실행한 계정을 이용자로 센다. 로그인하지 않고 페이지를 닫은 방문자는 포함하지 않는다.
- 최초 `app_opened` 날짜를 신규 이용일로 사용한다. 가입 날짜나 마지막 저장 시각을 방문 이력으로 추정하지 않는다.
- 기간: 최근 7/28/90일, 한국 날짜 기준. 기간 이용자/신규 이용자/오늘 이용자/활동 완료 이용자, 일별 인원, D1/D7/D14, 최초 유입 태그를 표시한다.
- Dn: 기간 안에 첫 이용한 계정 중 n일째가 도래한 계정만 분모에 포함하고, 정확히 n일째 접속한 계정을 분자로 센다. 분모 0은 0%가 아닌 집계 대기다. 오늘 수치는 진행 중이다.
- 접속 횟수와 접속자 수는 다르다. 반복 접속은 기록하되 지표는 고유 UID로 집계한다. 활동 완료와 쉬기는 별개 이벤트다.
- PRD 4장의 `app_opened`, `mission_viewed`, `activity_completed`, `rested`를 `src/lib/events.ts`로만 기록한다. 새 분석 이벤트 이름은 추가하지 않는다.
- `activity_id`는 현재 게임 저장의 완료 기록 ID이며 `mission_id`는 현재 콘텐츠 ID(예: D01) 또는 직접 작성인 경우 null이다. 별도의 PRD activities 행을 생성한 것은 아니다. level은 basic→large, small→small, stage는 해당 미션/선택 카테고리 단계다.
- 과거 진행을 복원하면서 완료 이벤트를 소급 생성하지 않는다. 측정 시작 전 데이터는 복원할 수 없다. 오프라인/분석 요청 차단 시 일부 이용이 집계되지 않을 수 있다.

## 유입 링크

```text
https://plant-butler-seven.vercel.app/?utm_source=kakao&utm_medium=share&utm_campaign=user_test
```

source/medium/campaign은 영문·숫자·하이픈·밑줄 48자 이내의 태그만 허용한다. 이름/이메일 등을 태그로 넣지 않는다. 최초 탭 진입 태그를 sessionStorage에 보관해 OAuth 왕복 뒤 전달하고 계정 첫 접속 때 서버에서 한 번만 저장한다. 로그인하지 않은 방문/페이지뷰, URL 전체, referrer 전체, 브라우저 지문, 클릭 자동 수집, 화면 녹화는 수집하지 않는다.

회고·직접 작성한 계획·사진·이메일은 이벤트 payload나 로그에 넣지 않는다. 설정에 수집 범위를 안내한다. 네트워크 실패는 게임 진행을 막지 않고 최대 100건의 비민감 이벤트를 메모리에서 재시도한다. 페이지 종료 시 남은 큐는 유실될 수 있다. 같은 키의 재시도는 DB에서 중복 반영하지 않는다. 분석 이벤트는 클라이언트 보고 값이므로 변조 불가능한 운영 감사 원장이 아니다.

## 가구 좌우 전환과 미션 질문

꾸미기 → 좌우 전환 → 가구를 누르기 → 저장. 다시 누르면 원래 방향이다. 이동/창고로 치우기는 좌우 전환을 끈 후 기존 방식으로 한다. 임시 배치, 되돌리기, 취소를 유지한다. `DecorItem.flipped`와 창고 소품의 선택 필드로 저장하며 구버전 필드 없음은 원래 방향이다. 실내와 창고 왕복, 공개 정원 방문에서도 방향을 보존한다. 추가 SQL 2번은 원본 저장 구조가 아니라 공개용 projection에 방향을 포함시키기 위해 필요하다.

미션 질문은 기존 고정 원고의 NPC 얼굴/이름/대사를 말풍선으로 표시한다. 미션 조건/완료/보상/AI 대화는 변경하지 않는다. 지도 ‘겹쳐 보기’ 표현은 이미 반영되어 있어 중복 수정하지 않았다.

## 검증

`npm run typecheck`, `npm run lint`, `npm test`, `npm run build`를 실행한다. 테스트 DB에서 `tests/team_analytics.sql`은 권한·중복·유입 태그·D1/D7 분모·팀 계정 제외·원본 접근 차단을 확인하고 롤백한다. 실제 Supabase 환경에서 두 계정(팀원/일반 참여자)으로 메뉴 노출과 RPC 차단, 서로 다른 날짜의 리텐션, 모바일 화면을 추가 확인한다.
