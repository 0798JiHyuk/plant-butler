# 정원 확장·실내·정원 이름 저장

## 변경과 저장 위치

- 기존 정원 아래 길을 확장 마당으로 연결한다. 기존 밭·식물·가구 좌표는 이동시키지 않는다.
- 집 문을 누르거나 가까이 이동하면 입장 확인을 받고 집 안으로 이동한다. 취소하면 밖에 남으며, 다시 문에서 떨어졌다 접근하면 재확인한다. 실내 아래 출구는 정원 집 앞으로 연결된다.
- 실내에서는 기존 공용 창고의 소품을 꺼내 배치하고 이동·회수한다. 실내 배치는 야외 배치와 별도로 보관하며, 출구를 막지 못한다. 씨앗·식물은 실내에서 소비하지 않는다.
- 정원 이름은 처음에 선택적으로 정하고 설정에서 변경한다. 공백만 있는 이름·제어문자·16자를 넘는 이름은 저장하지 않는다. 사용자의 실명 입력란이 아니다.

기존 `public.garden_saves.state` JSONB 안에 다음 선택 필드를 추가한다.

```json
{
  "garden": {
    "name": "함께 걷는 정원",
    "namePromptSeen": true,
    "interior": {
      "items": [
        { "id": "buy-1", "kind": "table", "variant": 0, "col": 12, "row": 12 }
      ]
    }
  }
}
```

위 예시는 설명용 부분 구조다. 기존 `state` 전체를 이 예시로 교체하면 안 된다. 현재 계정 동기화가 전체 진행을 저장하므로 새 테이블·컬럼·RPC·마이그레이션은 필요하지 않다. 기존 저장에 필드가 없으면 기존 이름과 빈 실내를 사용한다. 이름·가구는 계정 진행과 함께 저장되며 서버/로컬 충돌 선택은 기존 정책을 따른다.

현재 위치는 저장하지 않는다. 재접속·계정 전환·서버 복원 시 정원에서 시작하며, 실내 가구는 보존된다. 가구 구입·이동으로 새 보상을 만들지 않으며 미션·성장·가격 규칙은 변경하지 않는다.

## DB 확인용 읽기 SQL

Supabase SQL Editor에서 본인 사용자 ID로 필터해 확인한다.

```sql
SELECT user_id,
       state #>> '{garden,name}' AS garden_name,
       COALESCE(jsonb_array_length(state #> '{garden,interior,items}'), 0) AS indoor_furniture_count,
       revision, updated_at
FROM public.garden_saves
WHERE user_id = '본인 사용자 UUID'::uuid;
```

## 검증 범위

`src/tests/world.test.ts`는 이름 유효성, 기존·신규 저장 복원, 실내 가구 중복 배치·중복 회수·벽과 출입구 배치 차단, 식물 미소비, 하단 길 연속성을 확인한다.

격리된 브라우저에서는 이름과 HUD 반영, 하단 길 이동, 입장 확인·취소·퇴장, 창고 가구 배치와 모의 계정 서버 복원을 확인한다. 실제 휴대폰·운영 Supabase 왕복은 배포 후 별도로 확인한다. 기존 데이터의 수동 삭제·운영 DB 변경·배포는 수행하지 않는다.
