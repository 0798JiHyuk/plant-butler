# 틈새정원 미션 최종안

작성 기준: 2026-11-08 · 버전: 2026-11-08-90-v2-final

첫 접속에서 짧은 정원 소개를 본 뒤, 첫 미션을 추천받기 전에 **일상·학업·업무복귀 중 오늘의 영역을 직접 선택한다.** 영역은 고정 프로필이 아니며 언제든 바꿀 수 있다. 정원과 이야기만 먼저 보고 싶은 사람은 영역 선택을 건너뛸 수 있다.

각 영역 30개, 총 90개 미션은 작은 준비에서 실제 행동, 연결 행동, 선택·조절, 자기 미션, 자기 하루 설계로 발전한다. 이 순서는 실행 범위와 자기 설계 부담을 점진적으로 넓히는 추천 흐름이다. 모든 미션을 순서대로 끝내야 하는 30일 과제나 회복 등급이 아니다.

마지막에는 **자기 미션 두 개를 하루에 배치하고 선택한 한 개를 실행**한다. 세 번째 미션은 추가 선택이며, 부담스러우면 한 개만 만들어 최소 행동을 할 수 있다.

## 0. 개발자 빠른 적용

이 문서는 **구현할 동작의 명세와 90개 콘텐츠**다. 아래 타입·상태·의사 코드는 제안 명세이며, 기존 프로젝트에 이미 구현된 API나 함수라는 뜻은 아니다. 프레임워크·저장소는 기존 프로젝트 방식을 따른다.

### 0.1 먼저 구현할 범위

1. 첫 진입: 정원 소개 → 영역 선택 또는 정원 먼저 보기.
2. 영역·현재 상황에 맞는 카드 한 장과 기본·축소 선택.
3. 수행 자기보고 → 회차 종료 시 씨앗 한 번 지급.
4. 현재 활동의 다음 행동을 표지판으로 저장하고 재접속에서 복원.
5. 단계 전환 선택, 다른 카드, 쉬기, 영역 변경.
6. 직접 미션 편집 → 내 하루 배치 → 선택한 한 개 실행.

**기본 화면에 90개 목록을 전부 표시하지 않는다.** 현재 카드 한 장과 다른 것 고르기를 보여 주고, 전체 목록은 별도 메뉴에서 연다.

### 0.2 핵심 결정

| 항목 | 구현 기준 |
| --- | --- |
| 최초 영역 | 첫 맞춤 미션 전에 일상·학업·업무복귀 중 사용자가 선택. 자동 선택 없음 |
| 정원만 보기 | 영역 없이 정원·스토리 가능 |
| 영역 변경 | 언제든 가능. 기록·씨앗·직접 만든 미션 유지 |
| 난도 | 단계는 1~6. 날짜·연속 출석·정답·수행시간으로 자동 상승하지 않음 |
| 단계 전환 | 실제 다음 후보의 단계가 현재보다 높으면 사용자에게 미리 보여 주고 선택받음 |
| 카드 순서 | ID의 다음 번호는 정렬 후보. 목표·조건 필터가 먼저 |
| 직접 만들기 | 첫날부터 열림. 5~6단계는 안내가 줄어드는 과정 |
| 완료 | 선택한 실제 행동을 했다는 자기보고 |
| 보상 | `sessionId`당 씨앗 한 개. 카드 수·계획 저장 수와 무관 |
| 쉬기 | 미수행이면 보상 없이 종료·보존. 이미 수행한 행동이 있으면 기존 회차를 정상 정산하고 쉼 |
| 최종 단계 | 하루 미션 두 개를 기본으로 배치, 세 번째는 선택. 실행은 고른 한 개만 |
| 엔딩 | 미션·단계·30번 완료와 스토리 접근을 분리 |

### 0.3 데이터 파일

같은 폴더의 `틈새정원_90개미션_게임적용데이터_2026-11-08_v2.json`을 사용한다. `schemaVersion = 2`다. 이전 v1은 참고용이며 이 최종 명세와 함께 사용하지 않는다.

| 필드 | 용도 | 주의 |
| --- | --- | --- |
| `id` | D01~D30 / A01~A30 / W01~W30 | 콘텐츠 식별자. 날짜·필수 순서 아님 |
| `categoryId` | daily / academic / work | 화면의 한국어 표기는 `category` |
| `stage` | 추천 단계 1~6 | 능력·건강 상태 점수 아님 |
| `intentIds` | drink·meal·course·assignment·exam 등 | `all`이면 해당 영역의 공통 카드 |
| `npc / dialogue` | 캐릭터와 표시 대사 | 자료 내용을 자동으로 읽었다고 표현하지 않음 |
| `basic / small` | 두 실행 크기 | 둘 다 같은 회차 보상 |
| `done` | 카드별 완료 조건·문구 | 화면 버튼은 `completion.buttonLabel`을 기본으로 사용 가능 |
| `record / smallRecord` | 실제 선택에 맞는 기록 | 위치 찾기만 했는데 본행동 완료로 기록하지 않음 |
| `condition / conditionSummary` | 사람에게 보여 줄 사용 조건 | 이 문장을 문자열 분석해 추천 로직을 만들지 않음 |
| `eligibility` | 사용 상태와 필요한 조건 키 | 아래 조건 처리 규칙 사용 |
| `mode` | activity / create_and_execute / plan_and_execute / day_and_execute | 후반에는 설계 저장과 행동 수행을 분리 |
| `recommendation` | 후보 ID·필터·마지막 카드 처리 | `nominalNextId`를 곧바로 실행하지 않음 |
| `reward` | 활동 회차당 씨앗 한 개 | 지급 여부는 콘텐츠 객체가 아닌 회차 상태로 관리 |
| `evidenceCodes / why` | 기획·연구 근거 | 플레이 화면에 전부 노출할 필요 없음 |

`eligibility.basicRequiredFacts`와 `smallRequiredFacts`는 기본·축소에서 필요한 조건 키다. 각 키 값은 `true / false / unknown`으로 처리한다. **조건 키 전체를 처음에 설문으로 받지 않는다.** 현재 상황 선택에서 알 수 있는 값만 쓰고, 모르면 해당 카드의 사용 조건을 미리보기로 보여 준다.

- 필요한 조건이 `false`: 해당 실행 버전을 제외한다.
- 전부 `true`: 실행 가능한 후보로 둔다.
- `unknown` 포함: 자동 실행하지 않고 조건이 보이는 카드로 제안한다. 사용자는 선택·다른 것·해당 없음으로 갈 수 있다.
- 업무복귀의 W06~W20은 `workStatus = returned`일 때만 제안한다. 복귀 전·상태 미선택에서는 개인 준비·직접 만들기 분기로 간다.
- 직접 만든 미션은 가져온 행동의 조건을 이어받는다. 새 자유입력 행동에는 내용·완료 기준을 사용자가 정하며 앱이 치료·근무 적합성을 판정하지 않는다.

### 0.4 최소 런타임 상태

아래는 콘텐츠 파일과 별도로 저장할 상태의 예다.

```ts
type CategoryId = "daily" | "academic" | "work";
type Variant = "basic" | "small";
type FactValue = true | false | "unknown";

type Session = {
  sessionId: string;
  status: "active" | "closed" | "skipped";
  reportedActions: {
    missionId: string;
    variant: Variant;
    record: string;
  }[];
  rewardGranted: boolean;
};

type Bookmark = {
  categoryId: CategoryId;
  sourceMissionId: string;
  nextAction: string;       // 현재 활동의 다음 작은 행동
  locationLabel?: string;  // 사용자가 남긴 쪽·항목 등, 파일 내용 아님
};

type Progress = {
  selectedCategory: CategoryId | null;
  selectedIntent: string | null;
  workStatus: "pre_return" | "returned" | "unknown";
  recommendedStageByCategory: Record<CategoryId, number>;
  facts: Record<string, FactValue>;
  activeSession: Session | null;
  bookmarkByCategory: Partial<Record<CategoryId, Bookmark>>;
  // 자기 미션·하루 지도는 별도 저장. 구조는 기존 저장 방식에 맞춘다.
};
```

`recommendedStageByCategory`는 추천 위치다. 작은 행동으로 돌아갔다고 낮추거나, 미접속으로 초기화하지 않는다. 직접 만들기를 열었다는 이유만으로 5단계를 완료한 것으로 처리하지 않는다.

### 0.5 화면 상태와 이벤트

| 현재 상태 | 이벤트 | 다음 상태·처리 |
| --- | --- | --- |
| 정원 소개 | 미션 해보기 | 영역 선택 |
| 영역 선택 | 영역 고르기 | 상황 또는 조건부 카드 미리보기 |
| 영역 선택 | 정원 먼저 | 정원·스토리 |
| 카드 미리보기 | 기본·축소 선택 | 활동 중. 필요하면 새 회차 생성 |
| 활동 중 | 했어 | 실제 선택 행동의 기록 추가 → 더 하기·마치기 선택 |
| 마치기 선택 | 더 하기 | 같은 회차 유지 → 현재 기본 또는 다음 조건부 후보 |
| 마치기 선택 | 여기까지 | 회차 정산 → 표지판 선택 → 정원 |
| 수행 전 | 오늘은 쉬기 | 미수행 회차를 건너뜀 → 정원 |
| 수행 기록이 있는 회차 | 오늘은 쉬기 | 기존 수행 회차를 정산한 뒤 휴식으로 이동 |
| 편집기 | 저장만 | 설계 저장. 씨앗 없음. 설계는 보존 |
| 편집기 | 이 미션 실행 | 기존 회차를 이어 가거나 새 활동 회차 시작 |
| 중단 후 재접속 | 이어 하기 | 보류 회차를 이어 감. 이미 정산한 회차 재지급 없음 |
| 30번의 선택 행동 수행 | 마치기 | 같은 회차 보상 한 번 → 이후 내 하루 지도가 기본 화면 |

`오늘은 쉬기`를 눌렀다고 이미 했던 행동의 보상을 취소하지 않는다. 자기 하루 설계 카드와 그 안에서 실행한 자식 미션은 같은 실행 회차를 사용해 이중 보상을 막는다.

### 0.6 추천 처리 의사 코드

```text
추천 요청
  1. 자기 하루에서 사용자가 실행할 미션을 골랐다면 그 미션 우선
  2. 이어 하기를 골랐다면 현재 조건에 맞는 표지판 행동 우선
  3. categoryId가 없으면 영역 선택으로 이동
  4. categoryId가 같은 카드만 남김
  5. selectedIntent가 맞거나 intentIds에 all이 있는 카드만 남김
  6. workStatus와 기본/축소의 eligibility 적용
  7. 같은 단계의 다음 후보를 먼저 찾음
  8. 다음 단계 후보라면 미리보기 + 다음 길/여기서 연습 선택
  9. 후보가 없으면 다른 행동/이전 단계/직접 만들기/영역 변경
  10. 최종 30번 이후는 내 하루 지도. 26~29는 선택 편집 도구
```

`next`와 `nominalNextId`는 같은 의미의 정렬 후보다. 예를 들어 D01 다음 숫자는 D02지만, 음료 목표의 실제 다음 후보는 D06이다. 표지판은 D02를 자동 저장하지 않고 **현재 활동에서 다음에 할 작은 행동**을 제안한다.

### 0.7 보상 정산 규칙

```text
회차 종료 요청
  이미 closed/skipped면 저장된 결과 반환
  reportedActions가 0개면 skipped로 저장, 씨앗 0개
  reportedActions가 있으면
    rewardGranted가 false인 경우 씨앗 1개 지급
    rewardGranted = true와 closed를 함께 저장
  정원과 실제 행동 기록 표시
```

저장 방식이 서버든 로컬이든 중복 클릭·새로고침·재접속으로 같은 `sessionId`가 두 번 정산되지 않게 한다. 여기까지로 회차를 마친 뒤 다시 같은 행동을 고르는 것은 새 회차이며 허용한다.

| 시나리오 | 기대 결과 |
| --- | --- |
| 첫 접속 후 정원 먼저 선택 | 영역·미션 없이 정원·스토리 이용 |
| 일상 선택, 앉을 곳은 이미 비어 있음 | D05 강제 없음. 다른 장면·카드 선택 |
| 음료 목표로 D01 수행 후 더 하기 | D02 식사로 자동 이동하지 않고 D06을 다음 단계 후보로 제안 |
| 시험 중 과제 문서가 없음 | 과제 전용 카드 자동 제안 제외. 시험 맥락 유지 |
| 복귀 전인데 W06 이상 번호가 다음 후보 | 실무 카드 제외. 준비 계속·W21 준비 미션·다른 영역 |

| 완료 버튼 또는 정산 요청을 두 번 누름 | 같은 회차 씨앗 중복 지급 없음 |

| A30 편집 | 미션 두 개와 한 개 실행이 기본. 나머지 입력은 선택, 한 개로 축소 가능 |

| 오래 쉬고 다시 접속 | 단계·식물·기록 유지, 표지판 축소 행동 또는 다른 선택 |

위 항목은 구현 인수 기준이다. 현재 검증한 것은 문서·데이터 정합성이며, 게임 런타임에서 통과했다고 주장하지 않는다.


## 1. 첫 접속과 영역 선택

### 처음 들어왔을 때의 확정 흐름

1. 느리가 정원과 게임의 사용 방식을 짧게 소개한다.
2. 기본 정원과 첫 식물을 제공한다. 미션을 수행해야 얻는 보상과 구분한다.
3. 다음 화면에서 오늘의 영역을 고른다.
   - **일상:** 먹기·씻기·내 공간·전환·관계 같은 생활 속 행동.
   - **학업:** 수업·공부·과제·시험 준비.
   - **업무복귀:** 돌아갈 준비와 돌아온 뒤의 작은 시작.
   - **정원 먼저 둘러보기:** 영역 선택과 미션을 건너뛰고 정원·이야기 이용.
4. 영역 안에서 지금 필요한 장면을 고르거나, 조건이 적힌 카드 미리보기에서 하나를 고른다.
5. 맞는 카드 한 장을 보여 주고 `이만큼 할래 / 더 작게 할래 / 다른 걸 할래 / 오늘은 쉴래`를 제공한다.
6. 실제 선택 행동을 한 뒤 사용자가 확인한다.
7. `여기까지`면 회차를 마쳐 씨앗 하나를 받고, `더 해 볼래`면 같은 회차를 이어 간다.
8. 다음 행동 표지판은 남기거나 건너뛴다. 정원으로 돌아가 실제 행동 기록을 확인한다.

**확정 판단:** 첫 맞춤 미션 전에는 사용자가 영역을 선택한다. 게임 접속·정원·스토리 이용 전체의 필수 가입 절차로 만들지는 않는다. 영역 선택 자체에는 씨앗을 지급하지 않는다.

느리: “오늘은 어떤 쪽에 한 걸음 남겨 볼까?”

처음부터 `내가 직접 만들래`도 사용할 수 있다. 후반 단계는 직접 만들기 기능의 해금이 아니라, 사용자가 더 적은 안내로 스스로 설계하도록 돕는 흐름이다.

### 영역별 첫 미션

| 영역·현재 장면 | 처음 제안할 카드 | 상황이 맞지 않을 때 |
| --- | --- | --- |
| 일상 · 마실 것을 준비하고 싶음 | D01 쓸 컵 준비하기 | 먹기·씻기·공간 등 다른 장면 선택 |
| 일상 · 먹을 준비가 필요함 | D02 먹을 것 꺼내기 | 준비된 음식이 없으면 다른 장면 또는 자기 행동 만들기 |
| 일상 · 씻고 싶음 | D03 수건 펼쳐 두기 | 필요한 도구·방식이 다르면 직접 바꾸기 |

| 업무복귀 전 · 일정 안내가 있음 | W01 돌아갈 날 한 칸 | 안내가 없으면 W03 개인 준비 |

| 업무복귀 후 · 현재 요청이 있음 | W07 요청 한 문장 | 실제 배정 요청이 없으면 해당 카드를 제안하지 않음 |

일상에 단일 기본 미션을 강제하지 않는다. 상황 선택을 생략한 경우 D01·D03·D05의 짧은 조건부 미리보기를 보여 주고 사용자가 하나를 고르게 한다. 세 가지 모두 필요 없으면 다른 장면·직접 만들기·정원으로 갈 수 있다.

### 재접속했을 때

1. 저장한 **내 하루 지도**가 있으면 그 안에서 사용자가 실행하려는 미션을 먼저 제안한다.
2. 하루 지도가 없고 **표지판**이 있으면 현재 상황에도 맞는지 확인해 제안한다.
3. 둘 다 없으면 최근 영역의 조건에 맞는 카드를 보여 준다.
4. 모든 경우에 영역 변경·다른 행동·직접 만들기·쉬기를 제공한다.
5. 중단했다고 추천 단계나 식물·기록을 초기화하지 않는다.


## 2. 난도 검토 결과와 수정

**검토 결론:** 작은 행동에서 자기 미션·하루 설계로 나아가는 전체 방향은 적절한 설계 가설이다. 다만 “번호가 높으면 모든 사람에게 더 어렵다”는 뜻으로 운영하면 맞지 않는다. 행동 범위, 선택 부담, 계획 범위를 구분하고 현재 상황을 우선한다. 실제 사용자의 적정 난도는 아직 테스트하지 않았다.

| 확인한 지점 | 판단 | 최종 반영 |
| --- | --- | --- |
| 첫 미션 | 영역 선택 위치가 데이터에 명확하지 않았음 | 정원 소개 후 첫 맞춤 미션 전에 영역 선택. 영역은 변경 가능 |
| 일상 기본 D05 | 앉을 곳에 물건이 없는 사람에게 불필요 | 일상은 상황·카드 선택 후 추천. 무조건 D05 제안 제거 |
| 1~3단계 | 준비→한 행동→연결이라는 흐름은 타당 | 현재 할 일이 맞을 때만 진행. 반복 준비를 불필요하게 요구하지 않음 |
| 외출·연락·회의 | 단계 번호와 개인 체감 난도가 다를 수 있음 | 희망·장소·실제 일정 조건을 별도로 적용. D14 축소는 실내 이동으로 명시 |
| 4~5단계 | 선택·작성 부담이 증가하는 것은 의도에 맞음 | 기존 카드 가져오기·예시 재사용·선택형 입력·한 항목씩 편집 |
| A30 입력량 | 미션·계기·크기·휴식·대안을 한꺼번에 요구해 과함 | 미션 두 개 배치와 한 개 실행을 기본으로 통일. 나머지는 선택 편집 |
| 표지판 | 다음 번호를 그대로 저장하면 목표가 바뀔 수 있음 | 현재 활동의 다음 작은 행동을 저장. 다음 카드 저장 시 조건 확인 |
| 자기 설계 조건 | 준비된 사람·특정 단계만 가능하다고 읽힐 여지 | 사용자가 직접 만들기·하루 설계를 선택하면 첫날도 가능 |
| 쉬었다 복귀 | 이전 단계부터 재수행하면 부담 | 저장 행동의 축소 버전 우선, 단계·정원 보존 |

### 단계별 난도 기준

| 단계·카드 범위 | 높아지는 부분 | 기본 행동 | 부담이 큰 경우 |
| --- | --- | --- | --- |
| 1 · 01~05 | 행동 대상에 접근하기 | 찾기·꺼내기·첫 부분 보기 | 더 작은 준비 동작 선택 |
| 2 · 06~10 | 실제 한 행동 수행하기 | 읽기·쓰기·정리·사용 시작 | 같은 행동의 범위를 줄임 |
| 3 · 11~15 | 관련된 행동 연결하기 | 읽고 메모·준비 후 사용 | 한 동작으로 줄이거나 다른 카드 선택 |
| 4 · 16~20 | 자신의 방법 선택·조절하기 | 크기·방법·끝 지점 선택 후 실행 | 준비된 선택지 하나 사용 |
| 5 · 21~25 | 자신의 미션 만들기 | 행동·작은 버전·시작 계기 등을 하나씩 만들고 실행 | 기존 카드 복사 후 한 항목만 수정 |
| 6 · 26~30 | 하루 단위로 배치·수정하기 | 우선순위→두 자리→여유→수정→내 하루 | 미션 한 개만 만들고 최소 행동 실행 |

여섯 단계는 결과·시간·집중력의 등급이 아니다. 기본·축소 중 무엇을 수행해도 같은 회차 보상이며, 축소 선택만으로 추천 단계를 낮추지 않는다. 모든 다섯 카드를 완료해야 다음 단계에 갈 수 있는 잠금은 두지 않는다.

단계가 바뀌는 추천에서는 **“다음 길을 볼래 / 여기서 더 해 볼래”**를 묻는다. 현재 목표에 맞는 연습만 이어 가며, 너무 쉽다고 선택하면 다음 단계의 조건에 맞는 카드를 미리 볼 수 있다.


## 3. 사용자 선택에 따른 다음 추천

추천 우선순위는 **현재 영역 → 지금 하려는 일 → 실행 조건 → 현재 추천 단계 → 다음 후보**다. 숫자 순서는 콘텐츠 정렬용 기본값이며 바로 다음 미션을 강제하는 규칙이 아니다.

| 사용자 선택 | 처리 | 다음 화면·추천 |
| --- | --- | --- |
| 이만큼 할래 | 기본 행동 수행 | 완료 확인 후 여기까지·더 하기 |
| 더 작게 할래 | 같은 카드의 축소 행동 | 동일 보상, 단계 유지 |
| 여기까지 | 수행한 회차 종료 | 씨앗 하나 → 표지판 선택 → 정원 |
| 더 해 볼래 | 축소만 했다면 기본 행동, 기본을 했다면 조건에 맞는 다음 후보 | 단계 경계는 다음 길 선택을 먼저 받음. 같은 회차 보상 추가 없음 |
| 다른 걸 할래 | 같은 목표·단계에서 조건이 맞는 대안 최대 두 개 | 없으면 이전 단계의 맞는 행동·직접 만들기·다른 영역 |
| 너무 쉬워 | 다음 단계 카드 미리보기 | 사용자가 고르면 추천 단계 변경 |
| 다음에 이어갈래 | 현재 활동의 다음 작은 행동을 기본값으로 저장 | 다음 접속에도 조건 재확인. 단순 다음번호 저장 금지 |
| 오늘은 쉴래 | 휴식·건너뛰기로 기록하고 종료 | 정원·이전 단계·표지판 보존 |
| 다시 시작할래 | 저장한 다음 행동의 축소 버전 | 없거나 맞지 않으면 영역의 조건에 맞는 카드 선택 |
| 직접 만들래 | 미션 편집기 | 저장은 설계 기록. 실제 행동하면 회차 완료 |
| 30번을 마쳤어 | 내 하루 지도를 이후 기본 화면으로 | 자기 미션 실행, 26~29번은 우선순위·배치·여유·수정 도구 |

### 실제 추천 예시

- **일상·음료:** D01 컵 준비 → D06 원하는 음료 사용 → 사용한 자리 정리 D11 → D16~19 중 조절 → D21~25 자기 미션 → D26~30 자기 하루.
- **일상·식사:** D02 음식 준비 → D07 식사 시작 → D11 정리 → 현재 필요한 조절·자기 설계.
- **일상·씻기:** D03 수건 준비 → D08 세면 → 지금 필요한 연결 행동 또는 D16 조절. 다른 장면을 강제로 거치지 않음.
- **학업·시험:** A01 자료 찾기 → A02 열기 → A07 조건 → A08 첫 풀이 → A13 해설 연결 → A16 조절 → A21~30.
- **학업·과제:** A01 자료 찾기 → A03 안내 → A09 초안 → A11 자료 연결 또는 A14 소제목 → A16 조절 → A21~30.
- **업무복귀 전:** W03 개인 준비 또는 W01 안내 → 필요한 W01~05 → 준비 계속·W21 자기 준비 미션·다른 영역 중 선택. 복귀 전 실무를 요구하지 않음.
- **업무복귀 후:** W06 자료 → W07 요청 → W08 초안 → W11~15 중 실제 상황에 맞는 연결 → W16 조절 → W21~30.
- **쉬었다 돌아옴:** 이전 표지판의 축소 행동 → 원하면 같은 목표의 기본 행동. 이전 카드를 다시 전부 완료시키지 않음.

외출·연락·회의는 사용자가 원하고 조건이 맞을 때만 후보에 넣는다. 미션이 필요 없는 상황은 실패가 아니며, 해당 조건을 만들기 위해 불필요한 행동을 요구하지 않는다.


## 4. 공통 완료·보상·게임 연결

- **회차:** 행동을 고른 뒤 여기까지로 마치는 한 흐름. 여러 카드를 이어 해도 같은 회차 씨앗은 하나다. 하루 하나 제한은 아니다.
- **완료:** 선택한 현실 행동을 한 뒤 사용자가 확인한다. 타이머 종료·정답·성과·완성도는 조건이 아니다.
- **기본과 축소:** 보상은 동일하며 기록은 각각의 실제 행동과 일치해야 한다.
- **계획·표지판·회고:** 저장 자체에 씨앗을 추가 지급하지 않는다. 저장한 설계는 실행하지 않아도 보존한다.
- **쉬기:** 오늘 미션을 쉬거나 건너뛰는 선택에는 추가 씨앗이 없고 손실도 없다. 사용자가 직접 고른 휴식 행동을 실제 수행하는 D15 등은 활동 회차로 구분한다. 이 보상 차이가 적정한지는 사용자 테스트 항목이다.
- **인증:** 사진·파일·민감한 본문 제출 없이 자기보고로 처리한다. 통계는 사용자 보고 수행으로 표기한다.
- **유지:** 미접속·미완료로 정원·씨앗·기록을 잃지 않는다. 밀린 미션도 쌓지 않는다.
- **스토리:** 현실 미션 완료나 30번 도달을 메인 스토리·에필로그의 잠금 조건으로 삼지 않는다.

느리는 시작을 함께하고, 모루는 선택·크기 조절·미션 편집을 돕고, 피오는 기록·연결·하루 지도를 돕는다. 특정 단계에 특정 NPC만 등장해야 하는 것은 아니다.

마지막 자기 하루 지도는 기존 이야기의 **나만의 네 번째 지도**와 연결된다. 현실 행동→씨앗→심기·성장→열매→모루 상점·꾸미기라는 기존 게임 흐름을 유지한다. 높은 단계라는 이유로 씨앗 수량이나 희귀 확률을 올리는 규칙은 추가하지 않는다.

다음 표의 근거 코드는 9절에 정리했다. 연구는 구성 원리를 참고한 것이며 정확한 90개 미션과 단계 순서의 효과를 검증한 것은 아니다.
